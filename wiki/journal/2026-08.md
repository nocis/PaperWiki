# Journal — 2026-08

## 2026-08-04 | insight | Bug-fix round + from-zero reset

Four bugs fixed before the first ground-truth compile:

1. **Citation relation now built at compile stage.** The merged analyze call no
   longer normalizes/matches citations (it was matching against a stale,
   mid-run index — matches were silently nulled, so `cites[]` stayed empty).
   A slim dedicated citation call (`citationMapPrompt`) runs in a finalize
   pass against the FULL final index: map entry → `## Citations` section →
   `cites[]` → global `citedBy[]`. Compile is now self-contained.

   Follow-up failure found during verification: the first finalize attempt
   FAILED because the slim call's JSON output exceeded the model's output
   budget — 56–72 normalized records each echoing the raw bibliography entry
   (~10k+ output tokens) got truncated, and compile failed hard with the
   pages still showing "_No citations extracted._". Two fixes: (a) the `raw`
   echo was dropped — it is never rendered anywhere, cutting ~40% of output;
   (b) reference lists are processed in batches of 60 so a single call's
   output stays far under any model cap. Verified: full lists extracted
   (56/41/72), relations correct — DDIM → {Sohl-Dickstein 2015, DDPM},
   DDPM → {Sohl-Dickstein 2015}, citedBy reciprocity holds.
   Compile also self-heals now: the finalize pass processes any map entry
   with a persisted reference list but no records, so an interrupted run is
   repaired by simply re-running compile — no separate rebuild needed.
   Interrupted UI runs no longer wedge the UI: a stale "running" status is
   surfaced as failed (15-min guard) on the home page and API.
2. **Reference lists were truncated to exactly 25 entries** (prompt cap; DDPM
   lost its foundational predecessor, Sohl-Dickstein 2015). The prompt now
   demands EVERY bibliography entry (defensive cap 150) and lint flags a
   list hitting the cap. The reference list remains LLM-extracted only — the
   PDF is never re-read for citations (an early draft added a fragile
   code-side PDF bibliography heuristic; removed after review — LLM
   extraction with the raised cap is the design).
3. **Citation graph tooltip**: native SVG `<title>` on `<g>` is unreliable
   (Safari) — replaced with a custom mouse-positioned tooltip (title, topic,
   degree), zero dependencies.
4. **Knowledge pieces' origin**: Add-to-knowledge is the only sanctioned path.
   Pieces now carry provenance (note → paper + page, chat → exchange date),
   chat pieces are content-editable while note pieces stay immutable
   (delete + re-add), topic hints are managed separately for both kinds via
   `set-topics`, edits stamp `updatedAt` and mark the layer stale, and lint
   flags unsanctioned origins.

## 2026-08-04 | synthesis | Citation flow minimized + de-over-engineering pass

The citation pipeline was over-built: it normalized every bibliography entry
(title/authors/year/venue/doi) for display, when the display only needs the
raw list and the links. Redesign, per the human's direction:

- **Paper pages show the raw bibliography verbatim** (as extracted by the
  analyze LLM), with `→ [[slug]]` markers only on entries resolved to
  compiled papers.
- **The Citation Map holds only resolved matches** `{ entry, matchedSlug }`
  pointing into the raw list — no normalization anywhere.
- **The relation call is match-only**: numbered raw list + tiny index in,
  a few matched slugs out — output dropped from ~10k tokens to ~50–200 per
  paper, and truncation is impossible.
- **Matching is LLM-only**: entries the LLM does not resolve stay unlinked;
  compiled papers never cited are left alone. The old mechanical matcher
  (`resolveReferences`) was deleted along with other dead exports.

De-over-engineering pass (review requested by the human):
- Three near-identical progress modules (compile/citations/knowledge, 784
  lines) consolidated into one generic factory (`src/lib/progress.ts` +
  `src/lib/runs.ts`, ~450 lines total incl. configs) — same file paths and
  JSON shapes, zero client changes. Stale-run guard shared, not copy-pasted.
- `data/knowledge-db.json` dropped — it was a derived index duplicating the
  markdown; pages derive live from `knowledge/pieces` + `articles`.
- Prompt cleanup: match-only citation prompt, merged-prompt wording fixed,
  the generic JSON retry no longer hardcodes paper fields, section numbering
  tidied, dead exports removed (`pieceProvenance`, `addCitedBy`, `setCites`,
  `resolveReferences`, `normalizeTitle`, citation batching).

State reset to zero for a from-zero compile: the 3 diffusion PDFs are back in
`papers/new/`, the wiki, citation map, derived dbs and logs are cleared. The
3 knowledge pieces remain (tagged as chat exchanges) to seed the first
knowledge compile after the wiki ground truth exists.
